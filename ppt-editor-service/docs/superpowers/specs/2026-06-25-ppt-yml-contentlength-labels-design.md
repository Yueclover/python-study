# 设计：ppt-template-llm-edit.yml —— 篇幅控制 + 残留标签修复

日期：2026-06-25
目标文件：`ppt-editor-service/dify/ppt-template-llm-edit.yml`

## 背景

用「第三季度工作总结与计划-模板.pptx」做模板、输入"写 2026 年 AI 发展分析报告"，
经现有工作流产出 `53265bd1-out.pptx`。对比模板(8 页)与产出(32 页)发现两个最严重缺陷：

1. **页数失控**：8 页模板被复制成 32 页（约 29 页正文），版式高度雷同，像复读机。
   根因：第一个大纲节点 `17817757512960`(minimax)只看 `user_brief`、不受模板页数约束，
   一口气列了约 30 个主题；`llm_a` 据此逐项映射成页。
2. **残留章节标签**：每张正文页都印着与内容无关的模板侧标签
   （slide 3–9 印"三季度工作完成情况"、10–14 印"创新与成长"、15–20 印"存在主要问题"、
   21–26 印"四季度工作规划"、27–31 印"想法和建议"）。

## 关键事实（已用 parser+skeleton 验证）

- 这些侧标签槽位 **`editable=True`**（例：`s4_sh12="创新与成长"`、`s5_sh4="存在主要问题"`、
  `s6_sh3="四季度工作规划"`、`s3_sh4="三季度工作完成情况"`），确实被送进 `llm_fill_all`，
  是 LLM 主动"保留原值"。→ **改填充 prompt 即可修复，无需改解析层。**
- 该模板几乎所有页 `role` 被识别为 `generic`（封面未识别为 cover、正文未识别为 content），
  因模板用自由文本框而非标准占位符。属代码层(`skeleton.py`)问题，**本次不动**，记为后续项。

## 范围内改动

### 改动 1：新增篇幅档位输入
`start` 节点新增变量 `content_length`：
- 类型 select，选项 `short / normal / long`
- 选填（`required: false`），默认 `normal`（空值按 normal 处理）

### 改动 2：页数控制（纯 prompt，不改 graph 结构）
篇幅→正文页数映射写死在 prompt：`short→8 / normal→14 / long→20`，空值按 normal。
注入两个节点（均引用 `{{#start.content_length#}}` 并在文中说明映射与空值回退）：
- `17817757512960`（大纲）：正文要点控制在约 N 项。
- `llm_a`（大纲规划）：正文页数控制在 N 页左右（不含封面/目录/过渡/结尾）。

### 改动 3：修残留标签
改写 `llm_fill_all` 的 system 规则 2：
- **保留原值仅限**：页码数字(01–05)、日期、品牌口号"专注AI探索未来"、"目录/CONTENTS"、"感谢观看"。
- **栏目/章节标题类文字**（如"创新与成长""三季度工作完成情况"）**必须按本页 brief 改写**成
  贴合本页主题的短标签，不得保留模板原值。

## 不在本次范围（后续项）

- TOC 章节数与正文不对齐（模板 toc 写死 01–05 共 5 项，大纲可能给 6 章）。
- 章节过渡页（`role:section`）未被用作过渡。
- `skeleton.py` role 识别对自由文本框模板失效。

## 验证

- 无法在此环境跑 Dify。改动以 diff 形式给用户确认。
- 对修改后的 yml 做结构校验：YAML 可解析；start 新变量存在；
  `content_length` 引用在两个大纲节点出现；现有节点/边/变量引用未被破坏。
